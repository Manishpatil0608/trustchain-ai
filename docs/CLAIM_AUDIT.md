# TrustChain-AI Claim Audit

This document formally divides the theoretical claims proposed in the TrustChain-AI framework into three strict categories based on the final executable implementation.

## 1. IMPLEMENTED
The following capabilities exist functionally within the source code and were successfully executed during black-box validation:
- **DID/VC Authentication**: Agent capabilities successfully delegated and verified cryptographically via `did:key` Ed25519 signatures.
- **Capability Delegation**: Agents can legally delegate sub-capabilities.
- **Behavioral Trust Engine**: A dedicated mathematical engine evaluates `S_i(t)`, `C_i(t)`, and `L_i(t)`.
- **Temporal Trust**: Engine successfully decays historical reputation using $\lambda$ exponentially over time.
- **Adaptive Quarantine**: Intercepts requests with valid credentials but low trust, returning HTTP 403.
- **Recovery**: Agents mathematically escape quarantine after sustained protocol compliance.
- **Administrative Revocation**: Terminal immutable state.
- **Audit Trail**: Trust state transitions are persisted immutably in the local database.

## 2. EXPERIMENTALLY OBSERVED
The following outcomes were reproducibly generated by the testing suites and experiment runners:
- **H3 Result (SUPPORTED)**: Adaptive mitigation definitively prevents sustained malicious API executions faster than static credential expiration.
- **H4 Result (SUPPORTED)**: Trust score recovers proportionally to continuous benign behavior following a quarantine.
- **H5 Result (PARTIAL)**: Real-time calculation overhead was measured, but validation was localized to SQLite rather than distributed networks.
- **H1 / H2 Results (NOT SUPPORTED)**: Experimental runners confirmed the absence of a genuine distributed blockchain ledger in the architecture, rendering immutability and decentralized propagation claims fundamentally unsupported by the code.

## 3. FUTURE WORK
The following capabilities were proposed in literature but explicitly **omitted** from this release to preserve scope and architectural stability:
- **Trusted Telemetry Attestation**: Cryptographic signature validation of execution telemetry.
- **Replay Protection**: Hardened nonces for telemetry events.
- **Blockchain/Decentralized Ledger**: Replacing SQLite with a truly immutable consensus network.
- **Real-world Datasets**: Training/evaluating against empirical attack datasets.
- **Production Scalability**: Cloud deployments, Kubernetes, Redis, or Kafka message brokers.
- **Optimized Parameter Selection**: Using Machine Learning to dynamically tune the $\lambda$ and $w$ weights rather than static constants.
